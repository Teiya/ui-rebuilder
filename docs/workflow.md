# UI 重建工作流程

[简体中文](workflow.md) | [English](workflow.en.md)

UI Rebuilder 的目标不是把原稿重新画成一张相似图片，而是把原稿迁移成可以检查、编辑、复用和继续实现的 UI 系统。

## 1. 输入契约

每次重建至少需要：

1. 一张扁平化原稿；
2. 一个风格配置；
3. 一份布局描述或 layout-authority；
4. 预期输出类型。

玩法、交互状态和信息优先级应由消费项目先确定。工具不会从像素中擅自推断业务规则。

## 2. Spec：定义界面要做什么

在处理图片前，确认：

- 屏幕目标和主要操作；
- 信息层级；
- 默认、选中、锁定、禁用、失败等状态；
- 动态文字、数值、进度和列表；
- 最长文本、本地化和可访问性要求。

这些内容属于消费项目的 UX 契约，不写死在通用重建工具中。

## 3. Inventory 与 Catalog：识别可复用材料

`inventory` 记录当前原稿或项目里已经存在什么；`catalog` 将其中可信的面板、按钮、背景和提示组件整理成可检索模板。

第一版优先覆盖：`button`、`popup`、`background`、`tip`。

组件识别允许使用弱标签，但标签必须可检查，不能把猜测伪装成确定事实。

## 4. Layout：建立父子层级

布局有两种来源：

- `inline`：直接在任务文件中声明屏幕和节点；
- `layout-authority`：导入已有工具输出的节点和几何信息。

层级设计应遵循语义父节点，而不是只追求与截图坐标一致。例如“成功率圆环、标题、百分比”应属于同一个成功率组件；按钮文字应属于按钮组件。这样后续对齐、缩放和状态切换才可维护。

UIIR 保存节点类型、语义名称、父子关系、相对/绝对坐标、动态内容标记、样式、约束、资产绑定、来源方式、可信度和审核要求。

## 5. Asset：决定提取、修复还是生成

采用固定优先级：

| 顺序 | 方法 | 适用情况 | 约束 |
| --- | --- | --- | --- |
| 1 | 提取 `extracted` | 原稿中已有可靠像素 | 保留原始哈希与裁切区域 |
| 2 | 修复 `repaired` | 元素被文字遮挡、边缘污染或缺少透明底 | 优先确定性算法；记录修复来源 |
| 3 | 受控生成 `generated` | 原稿不存在完整素材，或需要同风格补齐 | 固定模型、种子、结构/风格条件并人工审核 |
| 4 | 矢量 `vector` | 可准确重建的简单几何 | 保持参数化和可编辑 |
| 5 | 运行时 `runtime` | 数值、进度、状态或业务图形 | 不烘焙进静态图片 |

常用处理规则：

- 圆形、头像和徽章等比缩放，禁止横纵方向分别拉伸；
- 可拉伸面板和长条框使用九宫格，并明确四边保护区；
- 有整体构图的按钮、图标和插画通常不适合九宫格，应等比缩放；
- 文字、数字、锁定状态、进度条填充值等保持独立；
- 裁切后检查 Alpha、暗边、色边和背景依赖；
- 生成结果不能静默替代提取结果，两者应作为不同候选保留来源。

## 6. Recipe：描述如何组装

Recipe 连接布局和组件材料，记录组件模板、slot 绑定、文字与状态载荷，以及仍需确认的假设。Recipe 不直接等于 Unity Prefab；运行时组装属于消费项目的 assembly 层。

## 7. OpenPencil：生成五页设计源

| 页面 | 内容 |
| --- | --- |
| `00_Foundations` | 颜色、间距、字体、圆角、描边等基础变量 |
| `10_Wireframe` | 不依赖最终美术的层级和布局结构 |
| `20_Visual` | 使用实际组件和资产组装的主界面 |
| `30_States` | 选中、锁定、禁用、失败等状态展示 |
| `90_Export` | 可复用 Component、资产尺寸和导出区 |

静态图片被嵌入 `.fig`，动态文字保持原生 Text。资产页使用 Component，视觉页和状态页使用 Instance，避免重复且不可维护的图片堆叠。

## 8. 自动质量门

构建会检查：

- 五页是否存在且有内容；
- 每个 UIIR 节点是否出现在线框和视觉页；
- 所有清单资产是否嵌入并拥有导出 Component；
- 节点层级和父节点相对几何是否一致；
- 导出组件尺寸是否与资产清单一致；
- 字体、颜色、间距、重叠和 Lint 报告是否已生成。

构建状态 `complete-fig-pending-visual-approval` 只代表结构门通过。

## 9. 人工视觉验收

人工验收至少比较原稿叠加、关键组件比例与视觉中心、色调与透明边缘、状态和最长文本、目标分辨率缩放。

发现问题后应回到对应层修正：布局问题改 UIIR/Recipe，资产问题改提取或修复阶段，风格问题改 Foundations，业务问题回到消费项目 UX 契约。

## 10. 引擎交付

通过验收后，消费项目根据 UIIR、资产清单、`.fig` 和状态页建立引擎层级，并再次验证锚点、本地化、状态切换、图片导入、九宫格边界及设计/预览/运行时三向一致性。

UI Rebuilder 当前输出引擎无关交付物；Unity uGUI Prefab 自动装配属于后续适配器范围。
